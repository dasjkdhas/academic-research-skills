## ① 契約情報 (一式、すべて必須)

これは一度取得すれば終わりです。電気料金の構造を理解しないと「経済効果」の計算ができないため、**P0 (最優先)**。

| # | 項目 | 単位 | 例 | 説明 |
|---|------|------|-----|------|
| 1.1 | **契約電力** | **kW** | 例: 2,000 kW | デマンド契約の上限値 (※ kV ではなく kW です) |
| 1.2 | **契約種別** | 区分 | 例: 高圧A、特別高圧 | 6.6kV / 20kV / 60kV 等の受電区分 |
| 1.3 | **電力会社** | 社名 | 例: 中国電力ネットワーク | 託送料金体系の特定 |
| 1.4 | **料金プラン名** | 名称 | 例: 業務用季時別電力 | 時間帯別/季節別料金の有無 |
| 1.5 | **基本料金単価** | 円/kW | 例: 1,650円/kW | 契約電力に乗じて計算 |
| 1.6 | **電力量料金単価** | 円/kWh | 時間帯別 | 夏季ピーク/夏季オフピーク/その他季 など |
| 1.7 | **力率割引/割増率** | % | 例: ±0.5%/1%力率変化 | 力率改善のインセンティブ |
| 1.8 | **デマンドピーク時間帯** | 時刻範囲 | 例: 7-9月 13-16時 | SDR発令の最重要時間帯 |
| 1.9 | **再エネ賦課金** | 円/kWh | 例: 3.49円/kWh | 単価とは別に賦課 |
| 1.10 | **燃料費調整額** | 円/kWh | 月次変動 | 直近12ヶ月の実績 |
| 1.11 | **契約開始日 / 更新日** | 日付 | - | 契約変更があれば各期間で別管理 |
| 1.12 | **デマンド計測方式** | 区分 | 例: 30分デマンド | 30分平均 or 1時間平均 |

**形式**: 契約書PDFのコピー + 上記項目を抜粋した Markdown または Excel 1枚

## ② 月度データ (24-36ヶ月分)

電力会社からの月次請求書ベース。**論文の Discussion で「年単位での節電効果」を語るのに必要**。

| # | 項目 | 単位 | 期間 | 説明 |
|---|------|------|------|------|
| 2.1 | **月間電力使用量** | kWh | 月ごと | 全棟合計 + 棟別 |
| 2.2 | **月間最大需要電力** | kW | 月ごと | デマンド値 (契約電力に対する使用率の分母) |
| 2.3 | **最大需要発生日時** | 日時 | 月ごと | 30分単位 (デマンドピークの根拠時刻) |
| 2.4 | **月平均力率** | % | 月ごと | 力率割引計算の根拠 |
| 2.5 | **月額電気料金** | 円 | 月ごと | 基本料金 / 電力量料金 / 燃調 / 再エネ 内訳 |
| 2.6 | **契約電力使用率** | % | 月ごと | デマンド ÷ 契約電力 |
| 2.7 | **月別平均気温** (参考) | °C | 月ごと | データセット検証用 (オプション) |

**形式**: CSV 1ファイル、列名は英語推奨 (`year`, `month`, `total_kwh`, `max_demand_kw`, etc.)

## ③ 日次データ (36ヶ月分)

BEMS から自動集計が可能なはず。**SDR判断の日級別妥当性検証**に使用。

| # | 項目 | 単位 | 説明 |
|---|------|------|------|
| 3.1 | **日間電力使用量** | kWh | 棟別 (b00-b15)、24時間積算 |
| 3.2 | **日間最大需要電力** | kW | 棟別、その日のピーク値 |
| 3.3 | **日間最大需要発生時刻** | HH:MM | 棟別 |
| 3.4 | **日間平均負荷** | kW | 24時間平均 |
| 3.5 | **日間最低負荷** | kW | ベースロード推定 |
| 3.6 | **負荷率** | % | 平均 ÷ 最大 (建物使用効率の指標) |

**形式**: CSV、1行 = 1日 × 1棟、または 横展開で 1行 = 1日 × 全棟

## ④ 時間データ (36ヶ月分) ← 🔴 **最重要・本研究の根幹**

予測モデルの学習データそのもの。**1時間値、欠測なし、3年分**が理想。

| # | 項目 | 単位 | 説明 |
|---|------|------|------|
| 4.1 | **時間別電力量** | **kWh** | 各1時間の合計使用量 |
| 4.2 | **時間別需要電力** | kW | 30分デマンドの最大 or 平均 |
| 4.3 | **対象棟** | - | b00 (主棟) は必須、b01-b15 も全部欲しい |
| 4.4 | **タイムスタンプ** | ISO 8601 | `2024-08-15 14:00:00+09:00` 形式 |
| 4.5 | **メーター区分** | 区分 | 全電力 / 空調 / 照明 / OA 等の分項計量があれば最高 |
| 4.6 | **欠測フラグ** | bool | 計測欠落/メンテ/異常値を明示 (ゼロで埋めない!) |

**形式 (厳守お願いします)**:
- CSV、UTF-8 (Shift-JIS は変換に時間がかかる)
- 第一欄: `timestamp` (ISO 8601、JST タイムゾーン `+09:00` 明記)
- 1年 = 1ファイル (`b00_2023.csv`, `b00_2024.csv`, `b00_2025.csv`)
- 欠測は **空白** または `NaN` (**ゼロで埋めないでください** — 過去にこれが原因でモデル汚染が発生)
- 1列 = 1変数 (時刻横展開しない)

**例**:
```csv
timestamp,b00_kwh,b00_kw_max
2024-08-15 13:00:00+09:00,1180.2,1240.5
2024-08-15 14:00:00+09:00,1213.5,1287.0
2024-08-15 15:00:00+09:00,,             ← 欠測は空白
```

## ⑤ 文脈データ (補足、可能な範囲で)

予測の異常値を解釈するために必要。「あの日の電力急降下は停電だった」等の区別。

| # | 項目 | 期間 | 説明 |
|---|------|------|------|
| 5.1 | **学事日程** | 2023-2025 | 学期/試験週/集中講義/夏季・冬季休 |
| 5.2 | **計画停電・メンテ記録** | 同上 | 日時、停止系統、影響範囲 |
| 5.3 | **過去のSDR/節電要請記録** | 同上 | あれば最高 (ground truth として使える) |
| 5.4 | **大規模イベント記録** | 同上 | 入試、卒業式、オープンキャンパス等 |
| 5.5 | **建物b00の物理仕様** | 一回 | 床面積、用途、空調設備、施工年 |

**形式**: 自由 (CSV / Excel / Markdown どれでも可)

## 💡 よくある質問への準備

設施課から「これは出せない/フォーマットが違う」と言われたときの対応:

| 想定質問 | こちらの対応 |
|---------|------------|
| 「BEMSデータは 30分値しかない」 | → **30分値で OK**。こちらで1時間平均に集計可。 |
| 「過去2年分しかない」 | → 2年でも十分。2024+2025で訓練、夏季のみで OK。 |
| 「単価情報は公開できない」 | → 一般公開されている託送料金で代用可、要連絡。 |
| 「棟別計量がない、全体のみ」 | → 全体でも OK。「キャンパス全体」を予測対象に変更。 |
| 「Excelしかない」 | → そのまま送ってください。こちらで CSV 変換します。 |
| 「Shift-JIS で生成される」 | → そのまま送ってください。UTF-8 に変換します。 |
| 「個人情報・契約情報の関係で出せない」 | → NDA 締結が可能か相談。最低限の集約値 (棟別月計) でも対応可。 |

## 🚦 受領後の作業 (こちらの側)

データを受領したら、こちらで以下を 1-2週間 で実施:

1. データクリーニング (欠測、異常値、外れ値検出)
2. 既存パイプラインへの統合 (`code/00b_load_power_data.py` を多年対応に拡張)
3. 多年データでの全モデル再学習 (Architecture C Hybrid)
4. 跨年汎化性能の評価 (Train: 2023-24, Test: 2025)
5. 経済効果計算 (契約電力 × 単価 × 予測ピーク削減率)
6. 論文の Methods / Results 章節更新
